# ฝั่งแอดมิน PeerTutor

เข้า `/admin` ด้วยบัญชีแอดมิน เช่น `admin.demo@example.com` รหัสผ่านเริ่มต้น `Demo12345!` เมื่อล็อกอินแอดมินระบบจะพามาหน้าภาพรวม หากบัญชีนี้เคยเปลี่ยนรหัสผ่านแล้ว ให้ใช้รหัสปัจจุบัน

## เมนูและการทำงาน

1. **ภาพรวม:** จำนวนผู้ใช้ โปรไฟล์นักเรียน/ติวเตอร์ นัดหมาย รายงานรอตรวจ และบัญชีพัก พร้อมรายงานล่าสุด ตัวเลขนักเรียนกับติวเตอร์อาจนับผู้ใช้คนเดียวกันได้ เพราะมีได้สองโปรไฟล์
2. **จัดการผู้ใช้:** ค้นหาชื่อ/อีเมล กรองประเภทและสถานะ ดูโปรไฟล์ พัก/เปิดบัญชี ไม่แก้บทบาทหรือรหัสผ่าน และไม่ให้พักบัญชีแอดมิน
3. **จัดการรายงาน:** กรองสถานะ ประเภท หรือข้อความ แล้วบันทึกสถานะล่าสุด `pending` → `in_progress` → `resolved` ใช้ `updated_at` เดิมแสดงเวลาแก้ไข ไม่มีบันทึกประวัติหรือช่องผลตรวจเพิ่มเติม
4. **จัดการรายวิชา:** เพิ่ม แก้ชื่อ ลบเฉพาะวิชาที่ไม่มีข้อมูลเชื่อมกับติวเตอร์ นักเรียน นัดหมาย หรือรายการโปรด
5. **ตรวจสอบรีวิว:** ค้นหาติวเตอร์ กรองคะแนนและการแสดงผล ซ่อนรีวิวด้วย `deleted_at` เดิมและเปิดคืนได้ คะแนนเฉลี่ยคำนวณใหม่จากรีวิวที่แสดงอยู่
6. **ตรวจสอบนัดหมาย:** ดูคู่ผู้เรียน/ติวเตอร์ วิชา วันเวลา และสถานะ ค้นหาและกรองได้ เป็นหน้าอ่านข้อมูล ไม่เปลี่ยนการจองของผู้ใช้

ประเภทการรายงานเป็นเมนูย่อยในหน้ารายงาน เพิ่ม/แก้ชื่อได้ ลบได้เฉพาะประเภทที่ยังไม่มีรายงานอ้างอิง

## โครงสร้างโค้ดสำหรับพรีเซนต์

- `resources/views/admin/layout.blade.php`: Sidebar และโครงหน้าร่วมกัน
- `public/CSS/admin.css`: สีหลัก `#0096FF` ใช้เฉพาะฝั่งแอดมิน
- `app/Http/Controllers/AdminController.php`: ดึงข้อมูล ตรวจค่าฟอร์ม และจัดการรายการต่าง ๆ
- `app/Domains/Reportreview/Http/Controllers/Admin/ReportController.php`: รับรายงานจากผู้ใช้และหน้ารายงานแอดมิน
- `AdminMiddleware.php`: ตรวจสิทธิ์จากบัญชีจริงทั้งหน้าอ่านและคำสั่งบันทึก
- `EnsureActiveAccount.php`: พักบัญชีที่ล็อกอินค้างอยู่ให้ออกจากระบบเมื่อส่งคำขอครั้งถัดไป
- `FortifyServiceProvider.php`: ตรวจรหัสผ่านและ `is_active` ก่อนล็อกอิน

ใช้ PHP, Laravel Blade, HTML และ CSS เป็นหลัก Popup ยืนยันใช้ `confirm()` สั้น ๆ ก่อนคำสั่งพักบัญชี ซ่อนรีวิว หรือลบข้อมูล

## วิธีอ่านโค้ดสำหรับพรีเซนต์

แต่ละเมธอดใน Controller เรียงเป็น 4 ขั้นตอน: ตรวจค่าจากฟอร์ม → เริ่มดึงข้อมูล → เพิ่มตัวกรองด้วย `if` → ส่งข้อมูลให้ View หรือบันทึกแล้วกลับหน้าเดิม

- `validate()` ตรวจว่าข้อมูลถูกชนิดและครบก่อนใช้งาน
- `with()` ดึงข้อมูลที่เกี่ยวข้อง เช่น นักเรียนและติวเตอร์ มาพร้อมรายการหลัก
- `where()` กรองข้อมูล ส่วน `where(function...)` รวมเงื่อนไข OR ให้อยู่ในกลุ่มเดียวกัน
- `paginate(12)` แบ่งรายการทีละ 12 รายการ และ `withQueryString()` เก็บตัวกรองเมื่อเปลี่ยนหน้า
- `DB::transaction()` ให้คำสั่งที่เกี่ยวข้องสำเร็จพร้อมกัน หากเกิดข้อผิดพลาดจะยกเลิกทั้งชุด
- `lockForUpdate()` กันการแก้รายการเดียวกันพร้อมกันระหว่างบันทึก โดยใช้ภายใน transaction
- `@foreach` วนแสดงรายการ `@if` เลือกข้อความหรือปุ่ม และ `@csrf` ส่งรหัสตรวจสอบฟอร์มของ Laravel

Sidebar เขียนเป็นลิงก์ 6 เมนูตรง ๆ ส่วน CSS ใช้รหัสสีโดยตรง พร้อมคอมเมนต์แบ่งส่วน ไม่ต้องอ่านระบบสร้างเมนูหรือคำสั่งกรองแบบย่อเพิ่มเติม

## ฐานข้อมูล

ใช้ตารางและคอลัมน์เดิมทั้งหมด ไม่มี migration ใหม่ ไม่เพิ่มตาราง ไม่เพิ่มคอลัมน์ และไม่ทำตารางประวัติ:

- `users.is_active`: พัก/เปิดบัญชี
- `reports.status`, `reports.updated_at`: สถานะล่าสุด
- `report_reasons`: ประเภทการรายงาน
- `subjects` และตารางเชื่อมเดิม: รายวิชา
- `reviews.deleted_at`: การแสดงผลรีวิว
- `tutor_profiles.average_rating`: คะแนนเฉลี่ยหลังจัดการรีวิว
- `appointments`: อ่านนัดหมาย

แก้ชื่อคอลัมน์ soft delete ใน Model Review ให้ตรงกับ `deleted_at` ที่ตารางมีอยู่แล้ว และเพิ่มความสัมพันธ์ Appointment กับนักเรียน/ติวเตอร์ โดยไม่ได้เปลี่ยนโครงสร้างตาราง
